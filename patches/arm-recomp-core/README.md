# Local patches to arm-recomp-core

Fixes we need in arm-recomp-core, gbarecomp's nested submodule at `gbarecomp/external/arm-recomp-core` (the ARM decoder, IR, reference interpreter and C code generator that gbarecomp's GBA profile uses), before upstream has them. They form a series of their own, applied by the same script and in the same way as [`patches/gbarecomp/`](../gbarecomp/README.md): `scripts/apply-patches.sh` applies every `*.patch` here in name order, each on top of the commit gbarecomp pins for arm-recomp-core plus the patches before it, to the nested submodule's working tree, after the gbarecomp series. We never commit inside it. After setup, `git -C gbarecomp status` shows `external/arm-recomp-core (modified content)`; that is this series.

How the series is applied, A/B builds, adding a patch and changing one in the middle are described in [patches/gbarecomp/README.md](../gbarecomp/README.md); what differs for this series is listed there under "The nested series". In short: `--without arm-recomp-core/0001` leaves a patch of this series out, `scripts/apply-patches.sh --write-patch patches/arm-recomp-core/NNNN-name.patch` saves a change made in `gbarecomp/external/arm-recomp-core/`, and its paths are relative to arm-recomp-core.

## Current patches

| Patch | What it fixes | Why we need it | Upstreamable |
|---|---|---|---|
| `0001-prefetch-reset-on-pc-write.patch` | A PC write empties the GamePak prefetch buffer: `Bus::prefetch_reset` (`profiles/armv4t_gba/bus.h`), called by `Interpreter::step` after any instruction that wrote R15, and the codegen clears `g_runtime_waits.last_prefetched_pc` after the refill of every direct branch (`profiles/armv4t_gba/arm_codegen.cpp`). The runtime's half is gbarecomp's `0011` | The prefetch model never forgot its position on a branch, where mGBA's `GBASetActiveRegion` does, so a cartridge loop that stores to RAM cost 26 cycles per iteration instead of mGBA's 22 (WAITCNT `0x4317`). Moto Racer Advance's race start-up clears EWRAM with such a loop, and the race started a frame late ([phase2-race-lockstep.md](../../docs/research/phase2-race-lockstep.md) §2). `scripts/repro-test.sh prefetch1` measures it on a synthetic ROM: mGBA's values with the fix, the pin's without (`--without 0011 --without arm-recomp-core/0001 --expect-failure`). Results: [phase2-timing-fixes.md](../../docs/research/phase2-timing-fixes.md) | Yes, with gbarecomp's `0011` (diagnosis §9, U19): the header has the mechanism and a repro without Nintendo data |
